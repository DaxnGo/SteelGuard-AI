### 4.5 Model Limitations

1. **Crazing detection:** Fine hairline cracks are the hardest class in NEU-DET; expect lower recall on `crazing` compared to other classes.
2. **Image resolution:** Model was trained on 640×640 upscaled from 200×200 originals — limited by source resolution.
3. **Grayscale domain:** NEU-DET is grayscale steel surfaces. Model may not generalise well to colour images or other materials.
4. **Single-defect assumption:** Most images contain one defect type; the model has limited exposure to overlapping multi-class scenarios.
5. **Nano model trade-off:** YOLO11n prioritises speed over accuracy. Larger variants (YOLO11s/m) would likely yield higher mAP.

## 5. Model Selection Justification — YOLO11n

### Why YOLO11n?

| Criterion | YOLO11n (chosen) | YOLOv8n | YOLOv5s | Faster R-CNN |
|---|---|---|---|---|
| **Parameters** | ~2.6M | ~3.2M | ~7.2M | ~41M |
| **FLOPs (640px)** | ~6.5G | ~8.7G | ~16.5G | ~134G |
| **Inference speed** | ~2ms (GPU) | ~3ms (GPU) | ~5ms (GPU) | ~50ms (GPU) |
| **Edge deployable** | ✓ | ✓ | Marginal | ✗ |
| **mAP@0.5 on NEU-DET** | Trained (see §4) | Not trained | Not trained | Not trained |

### Selection rationale

1. **Deployment constraint:** The API must run in a Docker container potentially without GPU. YOLO11n's nano architecture provides the best speed/accuracy trade-off for CPU inference.
2. **Ultralytics ecosystem:** Unified training, evaluation, and export pipeline. Native ONNX/TensorRT export for future optimization.
3. **Latest architecture:** YOLO11 (2024) incorporates C3k2 blocks and SPPF improvements over YOLOv8, achieving better mAP with fewer parameters.
4. **Production-ready:** Single-file checkpoint (`best.pt`), no external config files needed at inference time.

> **Note:** Only YOLO11n was trained for the current iteration. A multi-candidate comparison was deferred due to competition timeline constraints. The theoretical comparison above is based on published architecture specs. YOLO11n was selected because the product requires CPU-only Docker deployment with sub-100ms latency, making nano-class models the only viable candidates. Among nano models, YOLO11n offers the best parameter efficiency due to C3k2/SPPF improvements over YOLOv8n.

## 7. Class → Action Mapping

> **⚠️ IMPORTANT:** The mapping below is the **proposed default** based on standard hot-rolled steel surface QC practices. It **requires review and sign-off by the Quality / Domain Owner** before production deployment. The mapping is enforced at runtime via `STEELGUARD_RECOMMENDATION_MAP_JSON` — the API will not start without an explicitly configured mapping.

| Class | Proposed Action | Severity | Rationale |
|---|---|---|---|
| `Crazing` | **REWORK** | Medium | Fine surface cracks may propagate under stress; surface grinding/polishing can remediate if depth is within tolerance |
| `Inclusion` | **REJECT** | High | Foreign material embedded in the steel matrix is a material-level defect that cannot be removed by surface treatment |
| `Patches` | **REWORK** | Medium | Uneven surface finish (bright/dark patches) can often be corrected by re-rolling or surface conditioning |
| `Pitted Surface` | **REJECT** | High | Pitting indicates sub-surface porosity or corrosion susceptibility; compromises structural integrity |
| `Rolled-in Scale` | **REWORK** | Medium | Oxide scale pressed into the surface during rolling; removable by descaling, pickling, or grinding |
| `Scratches` | **ACCEPT** | Low | Shallow linear surface marks within normal handling tolerance; no structural impact for most applications |

### Action definitions

| Action | Definition |
|---|---|
| **ACCEPT** | Defect within acceptable tolerance; product passes QC |
| **REWORK** | Defect requires remediation (grinding, polishing, descaling, etc.) before acceptance |
| **REJECT** | Defect is critical; product fails QC and cannot be reworked cost-effectively |

### Runtime configuration

Set the following environment variable to activate this mapping:

```env
STEELGUARD_RECOMMENDATION_MAP_JSON={"Crazing":"REWORK","Inclusion":"REJECT","Patches":"REWORK","Pitted Surface":"REJECT","Rolled-in Scale":"REWORK","Scratches":"ACCEPT"}
```

> **Next step:** Domain Owner must review and approve this mapping before production deployment. Any changes to severity or action should be reflected both here and in the environment variable.

## Appendix: Reproducing the Full Pipeline

```bash
# 1. Install dependencies
pip install ultralytics>=8.4 scikit-learn Pillow

# 2. Prepare dataset (convert, split, integrity check)
python train_eval_pipeline.py prepare \
    --raw-images ./archive_extracted/NEU-DET/IMAGES \
    --raw-annots ./archive_extracted/NEU-DET/ANNOTATIONS \
    --output-dir ./datasets/NEU-DET

# 3. Train YOLO11n
python train_eval_pipeline.py train \
    --data ./dataset_neu.yaml \
    --epochs 100 --batch 16 --imgsz 640

# 4. Evaluate on test set
python train_eval_pipeline.py evaluate \
    --weights ./runs/detect/neu-det-yolo11n/weights/best.pt \
    --data ./dataset_neu.yaml

# 5. Verify checkpoint provenance
Get-FileHash -Path .\best.pt -Algorithm SHA256
```
